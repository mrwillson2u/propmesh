# PropMesh Pro — routing readiness audit, 2026-09-16

**Assessment:** this is a reasonable board for assisted, block-by-block routing,
but placement and routing constraints need another pass first. The schematic
checks are substantially healthier than the September 8 review. Routing the
current placement unchanged would preserve avoidable power-loop and noise risks.

**Scope:** saved Pro schematic and PCB, connection specifications, pinmap,
project rules, placement geometry, routing instructions, and local KiCad tools.
Mini currently has no KiCad design to inspect. This is not a fresh verification
of every purchased footprint, component rating, firmware path, or manufacturing
requirement. No schematic, PCB, library, or project-setting changes were made.

**1. High priority: re-place both regulator circuits before routing.**

Measurements below use centers of pads on the relevant electrical net, from the
saved PCB through KiCad's Python API. They are geometric distances, not routed
lengths or universal datasheet distance limits.

| Connection | Distance |
|---|---:|
| U5 SW → L1 input | 10.84 mm |
| U5 BST → C6 | 11.25 mm |
| L1 output → C9 / C10 | 21.61 / 19.55 mm |
| U6 SW → L2 input | 7.80 mm |
| L2 output → C16 | 13.13 mm |
| U6 FB → R19 / R21 | 20.39 / 20.82 mm |

The 5 V output capacitors remain across the IC from the inductor, and the 3.3 V
feedback divider sits far from its IC. Arrange each switcher as a compact circuit:
input bypass and its ground return at VIN/GND, short switch-node connection,
nearby output capacitors, and feedback components at FB with a quiet sense path.
This follows the manufacturers' [AP64350 layout guidance, page 22](https://www.diodes.com/datasheet/download/AP64350.pdf)
and [TLV62569 layout guidance, page 13](https://www.ti.com/lit/ds/symlink/tlv62569.pdf).

The existing 1 oz outer / 0.5 oz inner stackup also deserves an explicit thermal
check: the AP64350 guidance recommends heavier outer copper and ground on both
inner layers. That does not establish that this board's stackup will fail, but
thermal performance cannot be inferred from a clean DRC report.

**2. High priority: the fused-input net still misses its intended class.**

The schematic label was added, but its complete name is `/Power/VIN_FUSED`.
The project pattern `VIN_*` does not assign that net to HighCurrent.
KiCad's `GetNetClassName()` confirms **Default** for this net, while
`VIN_PROT` and `/Power/VIN_BUCK` resolve to HighCurrent plus inherited defaults.
Default requests a 0.25 mm trace on the input path intended to support the
10 A fuse option.

Add an explicit `/Power/VIN_FUSED` assignment and inspect every high-current
net's resolved class. Correct the instructions in `layout.md` A20 and
`sheets/01-power.md`: adding a local label alone did not complete the fix.

Also distinguish routing defaults from enforced limits. Netclass track widths
are preferred sizes, not DRC minimum widths, according to the
[KiCad manual](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#net_classes).
There is no project `.kicad_dru` file. Add appropriate rules and intentional
pad-neckdown exceptions, then review actual pour bottlenecks and return paths.
The prose's relay-to-logic spacing and sensitive-area exclusions are not encoded
as board keepouts or custom rules either.

**3. High priority: the common thermal-via prescription does not fit U9.**

`layout.md` A22 prescribes a 3 × 3 grid of 0.6 mm vias on 1 mm pitch, inside
the exposed pad, for U5/U7/U8/U9. That array spans **2.6 × 2.6 mm** including
the via copper. U9's actual pad 17 is **1.5 × 1.5 mm**. It cannot contain that
array. Specify a package-specific thermal-via and paste arrangement, checking
adjacent-pad clearance and the assembly process. Do not apply the shared
instruction automatically. No such vias have been placed yet.

**4. Medium priority: resolve mechanical errors and restore socket geometry.**

DRC reports courtyard overlaps for J44/J45, D14/J45, J14/J15, J15/J16,
and J16/J28. Inspect actual bodies and cable/screw access while separating them;
a courtyard collision alone does not prove that physical bodies collide.

Both StepStick row pairs now measure **12.75 mm**, against the specified
**12.70 mm**. This small mismatch is not proof a module cannot fit, but should
be corrected and the rows locked as groups so grid snapping cannot change it.
The setup checker does not test this dimension.

The twelve drill errors are U2's 0.20 mm plated thermal holes against the
project's 0.30 mm minimum. Choose a verified fabrication capability and reconcile
the rule/footprint deliberately. Give the mounting holes unique references and
handle them explicitly as board-only parts, or add them to the schematic.

**5. Medium priority: tighten decoupling and motor-supply placement.**

U2's 100 nF capacitor C2 is 7.83 mm from the 3V3 pad; its 10 µF C3 is nearer
at 5.29 mm. Both motor-driver ceramic bypass caps C21/C23 are 6.79 mm from VM.
Stepper bulk caps C18/C19 are 30.90/30.50 mm from the socket VMOT pins.
Bring these supply/return loops closer before routing. Revisit audio-output
separation after the power blocks move, then reposition affected test points.

**6. Medium priority: USB settings disagree with the routing plan.**

USB_DP/USB_DM currently resolve to Default, with differential width/gap
**0.20/0.25 mm**. A23 specifies **0.30/0.20 mm**, while the project minimum
track width is **0.25 mm**. Establish one USB class and geometry using the
actual fabrication stackup, verify the impedance calculation, and preserve the
ground reference through the connector/ESD/module path. This audit did not
calculate the pair impedance. The prose dimensions alone do not verify 90 Ω.

**What I could usefully do next**

I can inspect and edit native board geometry through the installed Python API,
create explicit tracks/vias/zones, inspect exported drawings, and run native ERC,
DRC, and parity checks. I would first correct the rules and critical placement,
then route and review the regulator blocks and power distribution, USB and other
sensitive signals, and finally the remaining I/O and test points. Each stage
should leave a reviewable board copy and a comparison against the DRC baseline.

This session establishes useful inspection and validation capability; it does
not demonstrate a completed route. Direct GUI control of KiCad's interactive
push-and-shove router is not available among this session's tools. Programmatic
track placement still needs geometric routing logic and iterative validation.
I would not promise an unattended production-ready layout. Load, thermal, audio,
USB, and motor-noise checks on the built board remain part of bring-up.
